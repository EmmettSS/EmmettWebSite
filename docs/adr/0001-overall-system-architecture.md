# ADR-0001: معماری کلان سیستم — Next.js (SSR) + Django/DRF در مونو-ریپو

**وضعیت:** پذیرفته‌شده
**تاریخ:** فاز ۰–۱ پروژه
**تصمیم‌گیرندگان:** مالک محصول + ایجنت ارشد توسعه

## زمینه (Context)

ریپوی اولیه یک SPA خام React/Vite بدون هیچ بک‌اندی بود (ر.ک. `DISCOVERY.md`). مأموریت پروژه صراحتاً Django/DRF، MySQL/SQLite، موتور AI مرکزی، و استقرار روی هاست اشتراکی cPanel ایرانی را الزامی کرده، همراه با الزامات سخت‌گیرانهٔ i18n (gettext)، SEO سمت سرور، و Accessibility/Performance.

## گزینه‌ها

1. **Django سنتی (Server-Rendered کامل):** Django templates + gettext کامل، بدون فرانت جدا. بیشترین تطابق با gettext و SEO out-of-the-box؛ کمترین پیچیدگی دیپلوی (یک پردازه)؛ اما نیازمند دورریختن کامل فرانت React/Motion فعلی و از دست دادن تعامل‌پذیری سطح بالای SPA.
2. **React/Vite SPA + Django/DRF API:** حفظ فرانت فعلی، بک‌اند فقط API. ریسک SEO بالا (نیاز به prerendering اضافه)، ولی حفظ سرمایه‌گذاری بصری موجود.
3. **Next.js (SSR/ISR) + Django/DRF API مجزا، در مونو-ریپو:** فرانت با SSR واقعی (SEO قوی out-of-the-box، hreflang/meta پویا در سطح صفحه)، بک‌اند API خالص و قابل تست مستقل، در یک ریپو برای هماهنگی نسخه و سادگی مدیریت.

## تصمیم

**گزینهٔ ۳ انتخاب شد:** Next.js (SSR) به‌عنوان فرانت‌اند + Django/DRF به‌عنوان API مجزا، هر دو در یک مونو-ریپو (`backend/`, `frontend/`).

## دلیل

- مالک محصول این گزینه را صریحاً تأیید کرد (نشست فاز ۰).
- هاست هدف قابلیت «Setup Node.js App» (Phusion Passenger) را دارد؛ بنابراین اجرای هم‌زمان دو پردازه (Django WSGI + Next.js Node) روی cPanel عملی است.
- Next.js SSR نیاز SEO سمت سرور (meta پویا، hreflang، JSON-LD) را بدون نیاز به بازنویسی کامل فرانت به Django templates برآورده می‌کند.
- جداسازی API از UI امکان تست مستقل، مستندسازی OpenAPI (قانون ۸)، و امکان توسعهٔ آیندهٔ اپ موبایل/کلاینت دیگر را فراهم می‌کند.

## پیامدها

- باید دو پردازهٔ جدا روی هاست مدیریت شوند (پیچیدگی عملیاتی بیشتر از یک پردازهٔ تکی Django).
- gettext (قانون ۹) برای متن‌های ثابت UI باید در دو محیط هماهنگ شود: Django `.po/.mo` برای بک‌اند/ادمین، و یک سیستم i18n در Next.js (مثل `next-intl`) با همان ساختار کلید — هماهنگی این دو لایه در `ADR-0003` و فاز Implementation فرانت مدیریت می‌شود.
- احراز هویت بین دامنه‌ها (CSRF/CORS/Cookie) باید با دقت امنیتی بیشتری طراحی شود (رجوع به فاز امنیت).
- فرانت فعلی React/Vite به‌طور کامل کنار گذاشته و در Next.js بازنویسی می‌شود؛ کد مرده و بصری قابل استفادهٔ آن (رنگ/تایپوگرافی/موشن) به‌عنوان مرجع طراحی حفظ می‌شود، نه کد مستقیم.
