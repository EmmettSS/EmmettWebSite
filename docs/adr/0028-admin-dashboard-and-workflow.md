# ADR-0028: داشبورد KPI، گردش‌کار انتشار و قابلیت‌های عملیاتی ادمین

**مرتبط با:** ADR-0006, 0008, 0012, 0013, 0027, 0029<br>

## ۱. زمینه

تا پایان فاز ۵، صفحهٔ اول ادمین فقط فهرست مدل‌ها بود. ادمین برای فهم وضعیت کسب‌وکار باید
چند صفحه را دستی مرور می‌کرد، برای «انتشار یک محتوا» فقط فیلد `status` را دستی عوض می‌کرد
(بدون ثبت رخداد معنادار)، و جدول‌های بزرگ بدون شمارنده/نمودار و بدون ابزار جست‌وجوی
پیشرفته بودند.

دو محدودیت صریح از سمت مالک محصول:

1. **بدون مدل مالی جدید** (پاسخ Q2: `no_money_model`) — آمار «فروش» از دادهٔ موجود
   (Lead/نرخ تبدیل/دوره/ثبت‌نام) محاسبه می‌شود و هیچ مبلغ ریالی/دلاری در DB ذخیره نمی‌شود.
2. **بدون migration و بدون وضعیت جدید** (پاسخ Q3: `no_migration`) — گردش‌کار انتشار روی
   همان وضعیت‌های موجود `draft/published/archived` پیاده می‌شود و هیچ فیلدی اضافه نمی‌شود.

## ۲. گزینه‌ها

| موضوع | گزینه‌ها | انتخاب |
|---|---|---|
| موتور داشبورد | اپ جدا (`dashboard`)، template tag، یا index override جازمین | **template tag** (`emmett_dashboard`) + قالب `templates/admin/index.html` |
| نمودار | Chart.js از CDN، کتابخانهٔ Python، یا SVG درون‌خطی | **SVG درون‌خطی تولیدشده در قالب** (بدون CDN، بدون JS سنگین) |
| محاسبهٔ KPI | در هر بار رندر، یا کش‌شده | **کش‌شده** با `ADMIN_DASHBOARD_CACHE_SECONDS` (پیش‌فرض ۱۲۰ ثانیه) |
| گردش‌کار انتشار | فیلد جدید `review` + migration، یا اکشن‌های گروهی روی وضعیت موجود | **اکشن گروهی** (`publish_selected` / `unpublish_selected` / `archive_selected`) |
| ثبت رخداد | تغییر مستقیم فیلد، یا اکشن + `AuditLog` | **اکشن + AuditLog** برای هر اقدام (ADR-0013) |
| حذف/بازیابی | حذف سخت، یا نرم‌حذف با اکشن بازگردانی | `SoftDeleteAdminMixin` + فیلتر «وضعیت رکورد» روی همهٔ مدل‌های `BaseModel` (ADR-0012) |

## ۳. تصمیم

1. **داشبورد**:
   - `apps/core/dashboard.py` یک `DashboardStats` تغییرناپذیر می‌سازد: کاربران
     (کل/فعال/کاربران جدید ۳۰ روز)، درخواست‌های AI (کل/خطا/هزینهٔ توکن)، Leadها
     (کل/تبدیل‌شده/نرخ تبدیل)، دوره‌ها (+ثبت‌نام)، و ردیف‌های فروشِ **سرنخ‌محور**
     (تعداد Lead→دوره با لینک به بخش لیدها، بدون هیچ مبلغ).
   - جمع‌آوری با کوئری‌های تجمیعی و `select_related` (قانون ۱۵)، کش‌شده زیر
     `admin_dashboard:stats:v1`؛ **سقف کوئری در تست قفل شده است** (`MAX_DASHBOARD_QUERIES` = ۱۷).
   - نمودار روند ۸ هفتهٔ اخیر به‌صورت SVG درون‌خطی از داده‌های متنی ساخته می‌شود
     (`CHART_WEEKS = 8`) — بدون CDN و بدون کتابخانهٔ گراف.
   - ویجت‌های «اقدامات اخیر»: `AuditLog` (همهٔ کاربران) و `admin.LogEntry` (فقط اقدامات
     خود کاربر جاری) با فیلتر زمان/کاربر.
2. **گردش‌کار انتشار** (`PublishWorkflowMixin` + `PublishableModel`):
   - نمایش ستون وضعیت رنگی با `render_status_pill(status, choices)`.
   - اکشن‌های گروهی با مجوز `change`: انتشار، بازگشت به پیش‌نویس، بایگانی؛ حفظ
     `published_at` اصلی در انتشار مجدد (تست‌شده) و ثبت یک `AuditLog` برای هر فراخوانی
     با `ids`، تعداد و نتیجه (`metadata`).
   - صفر migration، صفر فیلد جدید، صفر وضعیت جدید.
3. **کیفیت عملیات ادمین**:
   - `EmmettAdminDefaults` پیش‌فرض‌های مشترک (صفحه‌بندی ۲۵، `show_full_result_count=False`،
     `save_on_top`) و ادغام اکشن‌های گروهی mixinها در `get_actions`.
   - **اکشن‌ها باید unbound ثبت شوند**: قرارداد Django در `response_action` فراخوانی
     `func(self, request, queryset)` است (تست رگرسیون: POST واقعی روی changelist).
   - `RecordStateFilter` (حذف‌شده/فعال/همه) + `SoftDeleteAdminMixin.restore_selected` روی
     همهٔ مدل‌های `BaseModel` (استثنا: `core.AuditLog` — نگه‌داری قانونی).
   - `TranslationTabularInline`/`autocomplete_fields`/`list_editable`/`date_hierarchy` و
     `search_fields` دوزبانه (`title_fa`/`title_en`) روی همهٔ ادمین‌ها؛ ادمین بدون
     `search_fields` در تست «سطح ادمین» شکست می‌خورد.
4. **پیکربندی‌ها (Catalog/Prompt/Guardrail/EstimationRule)**: نسخه‌دار با کلید تغییرناپذیر
   پس از ساخت (readonly)، اکشن «بایگانی نسخه‌های قدیمی»، ستون «نسخهٔ مؤثر»، inline گزینه‌ها
   در کاتالوگ و ثبت هر تغییر در `AuditLog` (`AuditedConfigurationAdmin`).

## ۴. دلیل

- **صفر migration** الزام مالک محصول است و به‌طور کامل با وضعیت‌های موجود ممکن است:
  گردش‌کار به «اکشن + ثبت رخداد» نیاز دارد، نه فیلد جدید.
- **کش + سقف کوئری** تنها راه پاسخ‌گوی‌ماندن داشبورد روی هاست اشتراکی با دیتابیس MySQL
  بدون Redis است (ADR-0006).
- **SVG درون‌خطی** هم CDN را حذف می‌کند، هم وابستگی JS، هم CSP را ساده نگه می‌دارد و
  داده را بدون درخواست AJAX به کاربر نشان می‌دهد.
- mixinهای مشترک (`admin_mixins.py`) باعث یکسان‌بودن رفتار ادمین در همهٔ اپ‌ها و
  قابل‌آزمون‌بودن آن می‌شوند؛ سه باگ واقعی (اکشن bound، نرم‌حذف مدل‌های پیکربندی،
  `core.Translation` بدون `deleted_at`) دقیقاً با همین تست‌های ساختاری کشف شد.

## ۵. پیامدها

**مثبت:** مدیر کسب‌وکار بدون تغییر کد، وضعیت کاربران/Lead/AI/دوره‌ها را یک‌نگاه می‌بیند؛
انتشار محتوا یک اکشن است با رد حسابرسی؛ حذف اشتباهی با «بازگردانی» جبران می‌شود.

**منفی/ریسک:** (۱) کش ۱۲۰ ثانیه‌ای یعنی عددها لحظه‌ای نیستند — با
`ADMIN_DASHBOARD_CACHE_SECONDS=0` می‌توان خاموش کرد (تست‌شده). (۲) KPI بدون داده با
مقدار صفر رندر می‌شود و نباید خطا بدهد (تست‌شده). (۳) هر اپ جدیدی که `BaseModel` باشد
باید mixinهای ادمین را بگیرد؛ تست «سطح ادمین» همین را اجبار می‌کند.
