# EMMETT GROUP — UI/UX VISUAL REFINEMENT PROMPT

## ROLE

You are a senior product designer, UI/UX designer, and visual design director specializing in premium software companies, developer platforms, cybersecurity products, AI products, and modern technology brands.

You are refining an **existing Emmett Group UI**, not redesigning it from scratch.

The current UI already has a strong foundation:

* Dark premium aesthetic
* Strong sense of a professional technology team
* Good layout and hierarchy
* Modern typography
* High-quality cards and components
* Strong visual identity

**Do NOT destroy this foundation.**

Your task is to evolve the visual language into something more sophisticated, natural, premium, and distinctive.

---

# 1. CORE DESIGN DIRECTION

The current design feels somewhat too heavily inspired by:

* AI startups
* Generative AI dashboards
* Cyberpunk interfaces
* Neon futuristic SaaS products
* Excessive glowing effects
* Overuse of AI-style gradients
* "Everything is AI" visual language

We want to move AWAY from that.

Emmett Group should feel like:

> **A serious, elite, multidisciplinary software engineering and technology studio.**

The visual identity should communicate:

* Engineering excellence
* Technical depth
* Reliability
* Precision
* Creativity
* Sophistication
* Real-world software craftsmanship
* Security
* Architecture
* Product thinking
* Innovation

It should feel like a company/team that actually builds difficult software — not an AI landing-page template.

---

# 2. IMPORTANT — PRESERVE THE CURRENT FOUNDATION

Do not completely redesign the existing interface.

Keep the strongest parts of the current UI:

* Dark overall atmosphere
* Premium composition
* Strong typography
* Existing information hierarchy
* Good spacing system
* Existing navigation concept
* Existing card structure where appropriate
* Strong hero composition
* Professional overall feeling

Instead:

### REFINE

the visual language.

Think:

**80% existing strong foundation + 20% sophisticated visual evolution**

Not:

**100% completely new design.**

---

# 3. REDUCE THE "AI LOOK"

Avoid making every section look like an AI product.

Do NOT overuse:

* Neon glow
* Purple/blue AI gradients
* Excessive luminous borders
* Floating glowing particles
* Neural-network backgrounds
* Brain-like graphics
* Excessive nodes
* Holographic UI
* Sci-fi interfaces
* Generic AI waves
* Excessive glassmorphism
* Huge gradient text
* Glowing buttons everywhere
* Futuristic grid backgrounds in every section

These elements can still exist, but they should become **accent elements rather than the entire visual identity.**

AI-inspired visual effects should appear selectively.

For example:

* Hero → subtle technological visual
* AI service → slightly more futuristic treatment
* Pentestor → stronger cyber/security visual language
* Engineering sections → more architectural / structural visuals
* About / Team → much more natural and human
* Projects → product-focused and editorial
* Academy → clean educational/product design

---

# 4. INTRODUCE A MORE NATURAL TECHNOLOGY AESTHETIC

The design should combine:

### TECHNOLOGY + HUMAN CRAFT + ENGINEERING

Instead of:

### TECHNOLOGY + AI + NEON

Use visual inspiration from:

* Premium software studios
* Engineering companies
* High-end developer tools
* Architecture studios
* Industrial design
* Editorial technology magazines
* Modern operating systems
* High-end product design
* Technical documentation
* Swiss-inspired typography and grids
* Contemporary digital studios

The interface should feel **designed**, not algorithmically generated.

---

Keep the dark foundation, but make the palette more mature and less "AI SaaS".

### PRIMARY BACKGROUND

Use deep, warm-neutral blacks instead of pure futuristic black everywhere.

Possible foundation:

* Deep Obsidian
* Charcoal

* Modal/dialog surfaces

---

# 6. ACCENT COLORS

Keep the existing Emmett identity, but use accents much more intelligently.

Primary accents can remain around:

### Emerald

`#10B981`

### Indigo / Blue

`#6366F1`

However:

**DO NOT use them as giant glowing gradients everywhere.**

Instead introduce sophisticated secondary tones such as:

* muted emerald
* desaturated blue
* graphite
* cool gray
* warm gray
* soft silver
* subtle off-white

The overall palette should feel:

> restrained + premium + technical

rather than:

> neon + futuristic + AI.

Accent colors should guide attention rather than decorate every component.

---

# 7. BETTER BORDERS

The current glowing borders should become more sophisticated.

Instead of:

`1px bright glowing border`

prefer:

* subtle low-contrast borders
* layered borders
* inner highlights
* soft elevation
* tonal separation
* occasional accent border
* extremely subtle gradient borders

Example visual hierarchy:

Normal card:

* almost invisible border

Hover:

* slightly brighter border

Active:

* accent-colored border

Important feature:

* subtle accent glow

This creates hierarchy without making everything glow.

---

# 8. BETTER SHADOWS AND DEPTH

Introduce more realistic depth.

Use:

* soft ambient shadows
* subtle inner shadows
* layered elevation
* tonal contrast
* restrained blur
* background separation

Avoid:

* huge neon shadows
* excessive bloom
* unrealistic glowing cards

Cards should feel like **physical layers in a sophisticated digital workspace**.

---

# 9. GLASSMORPHISM — USE SELECTIVELY

Glassmorphism is allowed but should NOT dominate the interface.

Use it primarily for:

* floating navigation
* selected overlays
* special hero elements
* modal surfaces
* floating controls

Most content cards should instead use:

> solid / semi-solid premium surfaces + subtle borders + depth

This will make the UI feel much more mature.

---

# 10. INTRODUCE MORE EDITORIAL / ARCHITECTURAL ELEMENTS

This is very important.

The interface should have visual elements that communicate **engineering and structure**, not only AI.

Consider:

* architectural grids
* technical diagrams
* system architecture motifs
* modular layouts
* measured spacing
* technical labels
* small metadata
* numbered sections
* coordinates
* subtle rules
* horizontal separators
* structured typography
* engineering-style annotations
* blueprint-inspired details
* product screenshots
* code fragments used sparingly
* system maps
* clean diagrams

These elements should feel intentional and premium.

---

# 11. TYPOGRAPHY

Typography should become one of the strongest visual elements.

Use:

* strong modern sans-serif typography
* large but controlled headlines
* excellent hierarchy
* tight but readable display typography
* small technical metadata
* uppercase labels where appropriate
* generous whitespace

Do not make every heading huge.

Create contrast between:

* Display
* Heading
* Body
* Caption
* Technical metadata

Typography should communicate:

> confidence and precision

rather than:

> futuristic startup.

---

# 12. MOTION & INTERACTIONS

Use motion to create quality, not spectacle.

Preferred:

* subtle hover transitions
* smooth elevation
* slight image movement
* subtle border transitions
* controlled parallax
* content reveal
* understated cursor interactions
* micro-interactions

Avoid:

* excessive particle animations
* constant glowing animations
* aggressive floating objects
* excessive 3D
* overactive backgrounds

Motion should feel:

> deliberate + smooth + expensive

# 18. VERY IMPORTANT — DO NOT REPEAT THE PREVIOUS IMPLEMENTATION PROBLEM

The previous implementation had almost everything placed inside a single `App.tsx`, which made the project difficult to separate and maintain.

The Figma design must therefore reflect a **modular architecture**.

Design each page independently and make component boundaries obvious.

The visual architecture should naturally map to a future implementation such as:

* `/pages`
* `/components`
* `/sections`
* `/layouts`
* `/components/ui`
* `/assets`

Each page should be independently understandable.

Do not create one enormous monolithic page containing every section.
