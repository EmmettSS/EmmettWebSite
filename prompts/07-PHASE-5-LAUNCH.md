## ۴. SEO نهایی

- sitemap دوزبانه با hreflang سازگار · `robots.txt` · `x-default`
- JSON-LD معتبر: `Organization` · `WebSite` · `BlogPosting` · `BreadcrumbList` · `Person` ·
  `SoftwareApplication` (برای هر ابزار) · `ItemList` (برای `/tools/`)
- OG image برای **هر** روت (با تایپوگرافی فارسی)
- canonical درست به ازای locale · **صفر 404 قابل ایندکس** · redirect نگاشت روت‌های قدیمی
- ⚠️ **خروجی اشتراکی ابزارها `noindex` بماند** (از فاز ۲) — بررسی شود که در لانچ نشکسته باشد.
- یک اسکریپت CI که همهٔ این‌ها را بررسی می‌کند و در صورت تخلف fail می‌شود.

## ۵. Matomo و اندازه‌گیری

- Matomo **self-hosted روی همان cPanel**، cookieless، بدون third-party pixel خارج از origin.
- رویدادها با نام ثابت:

```
tool_use            { tool, completed }
tool_share          { tool, method }
palette_open
terminal_command    { command }
scan_run            { result_grade }
scan_share
pentestor_cta       { source }        # ⭐ رویداد تجاری F-06
assistant_ask       { had_citation }  # ⭐ معیار کیفیت RAG
assistant_fallback  { reason }        # provider_down | budget | low_similarity
bio_analyze         { length_bucket }
contact_submit      { source }
telegram_click      { source }        # ⭐ F-13
capability_click    { capability }
```

⚠️ **متریک‌های هدف §۱ MASTER باید از همین رویدادها قابل محاسبه باشند.** اگر نیستند، رویداد اضافه کنید.

## ۶. عملیات

- **بکاپ:** cron + `db_backup` · نگهداری ۷ روزانه / ۴ هفتگی.
  ⚠️ **تست restore واقعاً اجرا شود** و در گزارش ثبت شود. «بکاپ داریم» بدون تست restore یعنی هیچ.
- **مانیتورینگ:** uptime خارجی روی `/api/v1/health/` و `/` (200 + عنوان درست).
- **لاگ:** روش بازبینی خطا در runbook + یک endpoint شمارش خطا (admin-only).
- **deploy + rollback:** یک‌بار روی staging **اجرا شود** و مستند شود.
- **cron:** همهٔ خطوط `deploy/crontab.txt` روی سرور فعال و **راستی‌آزمایی** شوند
  (مهم‌ترین: `process_jobs` — چون F-06 و F-08 به آن وابسته‌اند).

## ۷. Hardening امنیتی

- بازبینی OWASP Top-10 برای **هر** endpoint (جدول در `docs/SECURITY.md`)
- هدرهای امنیتی + CSP · `pip-audit` و `npm audit` بدون high/critical · secrets scan تمیز
- **شش نگهبان F-06 در محیط تولید راستی‌آزمایی شوند** (نه فقط در تست)
- **سقف هزینهٔ AI در تولید تنظیم و تست شود** — ⚠️ این را جدی بگیرید؛ یک حلقهٔ تصادفی
  می‌تواند قبض بسازد. یک تست دستی با رسیدن به سقف انجام دهید.
- صفحهٔ `security.txt` + سیاست افشای آسیب‌پذیری (ارزان و پرسیگنال — انجامش دهید)
- صفحات حقوقی (حریم خصوصی، شرایط استفاده) دوزبانه زنده

## ۸. استقرار روی cPanel

طبق `deploy/DEPLOY-CPANEL.fa.md` — **واقعاً اجرا شود**، نه فقط نوشته شود.

ترتیب: بکاپ → deploy کد → venv → `migrate` → `collectstatic` → static bridge →
فعال‌سازی cron → smoke test (`/api/v1/health/` + `/` + یک ابزار + یک اسکن واقعی) → cutover.

⚠️ **اسموک تست باید شامل یک اسکن واقعی F-06 باشد** — چون مسیر job+cron را end-to-end
راستی‌آزمایی می‌کند و اگر cron درست نباشد، اینجا لو می‌رود.
