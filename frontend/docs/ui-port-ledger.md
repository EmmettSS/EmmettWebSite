# دفترچهٔ پورت «UI» → فرانت‌اند Next.js

این سند، «دفتر کل» پورت ۱:۱ بستهٔ طراحی `EmmettWebSite/frontend/` (خروجی Figma Make؛ تا فاز ۵ در
ریشهٔ ریپو با نام `UI/`) به فرانت‌اند Next.js (`EmmettWebSite/frontend/`) است: چه چیزی
منتقل شده، چه چیزی عمداً منتقل نشده و چرا، و چه چیزهایی برای فازهای بعد باز مانده است.

> **نوع سند: دفترِ رویدادِ فازی، نه مرجعِ زنده.** هر عددی در این دفتر (شمارِ
> تست‌ها، شمارِ URLهای Lighthouse، شمارهٔ اجرای CI) اندازه‌گیریِ **پایانِ همان
> فاز** است و عمداً بازنویسی نمی‌شود — همان قاعده‌ای که برای مدخل‌های تاریخیِ
> `CHANGELOG.md` و برای خودِ ADRها هم صادق است. برای اندازهٔ **کنونیِ** سوئیتِ E2E
> به [`../e2e/README.md`](../e2e/README.md) بروید؛ برای فهرستِ معتبرِ ADRها به
> [`../../docs/adr/README.md`](../../docs/adr/README.md).

## قواعد ثابت این پورت

1. **بک‌اند (Django/DRF) صفر تغییر** — نه مدل، نه ویو، نه مهاجرت. هر جایی که بک‌اند
   کمبود داشته باشد، مسئله در سمت فرانت حل می‌شود.
2. **ظاهر پورت‌شده مو‌به‌مو همان UI است** — کلاس‌ها، هگزها، فاصله‌ها و موشن‌ها بدون
   تغییر. تبدیل‌های مجاز علاوه بر `to=` → `href=`، `"use client"` و
   `react-router` → `@/i18n/navigation`، در بخش فاز ۲ فهرست شده‌اند.
3. **دو زبانه (fa/en) و کاملاً داینامیک** — محتوای هر بخش از API بک‌اند می‌آید
   (`Accept-Language`)، متن هاردکد UI فقط fallback است.
4. **آزمون پذیرش بصری** — پس از هر فاز، مقایسهٔ خروجی build با حالت قبل؛ حذف/تغییر
   هر قاعدهٔ CSS موجود ممنوع است.

### ب) توکن‌ها و «چرا scoped؟»

در فاز ۱ مقادیر UI زیر کلاس `.ui-theme` تعریف شده‌اند (نه در `:root`)، به دو دلیل:

1. باید **هیچ‌چیز از UI جا نیفتد**: همهٔ ۴۸ توکن با همان نام‌ها/مقادیر + کل لایهٔ base،
   زیرمجموعهٔ `.dark` (که مقادیرش با `:root` مو‌به‌مو یکی است — با ابزار بررسی شد:
   ۳۴ کلید مشترک، صفر تفاوت)، و قاعده‌های `h1..h4/label/button/input`.
2. باید **مسیرهای فعلی هیچ تغییر بصری نگیرند**: ۱۸ مسیر فعال هنوز با دیزاین‌سیستم
   قبلی (ADR-0017) کار می‌کنند و بازطراحی‌شان فاز ۷ است.

سازوکار فنی: نگاشت‌های `@theme inline` در `globals.css` هر کلاس معنایی را به
متغیر زنده تبدیل کرده‌اند (`.bg-background → background-color: var(--background)`،
`.rounded-lg → border-radius: var(--radius-value-lg)`، `.border-border → border-color:
var(--border)`). پس هر عنصر داخل `.ui-theme` خودکار مقدار درست UI را می‌گیرد —
**بدون تغییر حتی یک کلاس در کد پورت‌شده**. این ادعا در خروجی build راستی‌آزمایی شد.

نکتهٔ حیاتی گردی‌ها: UI برای `rounded-md` و `rounded-lg` مقادیر ۶px و ۸px دارد اما
دیزاین‌سیستم فعلی ۸px و ۱۶px؛ به همین دلیل `--radius-value-sm/md/lg` داخل `.ui-theme`
بازتعریف شد تا `rounded-md`/`rounded-lg` در ناحیهٔ پورت مو‌به‌مو مثل UI شوند.

## تصمیم‌های ثبت‌شدهٔ مالک محصول (پیش از فاز ۲)

1. **بریک‌پوینت‌ها — وفاداری کامل به UI با تضمین رسپانسیو بودن.** مقیاس بریک‌پوینت فرانت
   به پیش‌فرض Tailwind (همان مقیاس UI: sm=640، md=768، lg=1024، xl=1280، 2xl=1536)
   برمی‌گردد تا پورت Home مو‌به‌مو باشد. چون این تغییر مقیاس، رفتار عرض‌های میانی
   مسیرهای فعلی را هم تغییر می‌دهد، در فاز ۲ پیش از پورت:
   - فهرست کامل کاربردهای `sm/md/lg/xl` در ۱۸ مسیر فعلی استخراج و در عرض‌های مرزی
     (۳۲۰، ۳۹۰، ۶۴۰، ۷۶۸، ۱۰۲۴، ۱۲۸۰، ۱۴۴۰، ۱۹۲۰) بازبینی می‌شود؛
   - هر نقطهٔ شکست احتمالی (چیدمان‌های وابسته به px دقیق) اصلاح و مستند می‌شود؛
   - تأیید نهایی روی پیش‌نمایش زنده در همین عرض‌ها (چون دانلود مرورگر Playwright در
     محیط فعلی ممکن نیست، بازبینی بصری به‌صورت دستی/پیش‌نمایش انجام می‌شود).
2. **حالت روشن/تیره — تک‌حالت تیره، دقیقاً مثل UI.** دکمهٔ تغییر تم (`ThemeToggle`)
   در فاز ۷ (بازطراحی مسیرهای فعلی) حذف می‌شود؛ تا آن زمان دست‌نخورده می‌ماند تا در
   مسیرهای فعلی تغییر بصری ناخواسته رخ ندهد. توکن‌های UI طوری نگه داشته می‌شوند که
   افزودن پالت روشن در آینده (در صورت نیاز) بدون بازنویسی ممکن باشد.

## فاز ۲ — گزارش کامل

### الف) چه چیزی پورت شد

۱۳ فایل زنده (۱۱ کامپوننت Home + `Home` + `ComingSoon`) در
`src/components/ui-port/`، با پوستهٔ `(ui)` روی `/` و دو مسیر جدیدی که در فرانت
نبودند: `/products/pentestor` و `/products/crm`. ۱۸ مسیر قبلی به گروه `(site)`
جابه‌جا شدند و پوستهٔ خودشان (هدر/فوتر ADR-0017) را حفظ کردند. بک‌اند تغییر نکرد.

تبدیل‌های مجاز این فاز، غیر از سه تبدیل مکانیکی فاز ۱:

- برچسب ناوبری از `nav.*` (en مو‌به‌مو همان رشتهٔ UI؛ fa برچسب موجود سایت).
- `left/right/ml/pr` فیزیکی → `start/end/ms/pe` تا fa (RTL) آینه شود و en مثل UI بماند.
- `/library` → `/blog` (قرارداد URL بک‌اند؛ تست موجود «کتابخانه → /blog»).
- `NeuralNetwork3D` با `next/dynamic` و `ssr: false` (three.js در باندل اولیه نیاید).
- لودر: محتوا زیر پوشش مات رندر می‌شود (SEO / بدون JS) و با `prefers-reduced-motion`
  پنهان می‌شود. کلید `sessionStorage` ندارد.
- لینک پرش به محتوا و `<main>` — فقط برای کیبورد / لندمارک؛ روی ظاهر اشاره‌گر اثری نیست.

عمداً منتقل نشد: کامپوننت‌های مردهٔ UI (در `App.tsx` رندر نمی‌شوند) و ۹ مسیر ComingSoon
دیگر (فاز ۵). متن بدنهٔ هوم انگلیسی ماند (۱:۱ با UI). ⌘K هنوز فهرست ثابت است (فاز ۴).

### ب) بازبینی عرض‌های مرزی (استاتیک)

دست نخوردند. مرورگر Playwright در این محیط نیست؛ بازبینی روی همهٔ کلاس‌های
`sm/md/lg/xl` مسیرهای فعلی و اندازه‌گیری عرض فونت Vazirmatn (وزن ۷۰۰ به‌عنوان سقف) بود.
عرض‌های ۳۲۰ و ۳۹۰ زیر همهٔ بریک‌پوینت‌ها هستند و نسبت به قبل عوض نشدند.

### ج) برابری مسیرهای فعلی

HTML بیلد فاز ۱ و بیلد فاز ۲ برای ۱۵ مسیر قدیمی (غیر از `/` و `/en` که عمداً عوض
شده‌اند)، بعد از حذف اسکریپت: ۱۳ مسیر بایت‌به‌بایت یکی. `design-system` فقط `useId` و
ساعت زنده فرق دارد. `/products` فقط جای متادیتای استریم‌شدهٔ Next فرق دارد (بدنه یکی است).
هیچ متغیر CSS قدیمی حذف نشد. `.shrink-0` در CSS جدید هست (با `.flex-shrink-0` ادغام شده).

### د) focus و پورتال

- بستهٔ UI قاعدهٔ focus ندارد. حلقهٔ `:focus-visible` سراسری فرانت داخل `.ui-theme` هم
  اعمال می‌شود و فقط با کیبورد دیده می‌شود. حذفش معیار دسترس‌پذیری پروژه را می‌شکند؛ ماند.
- پالت ⌘K داخل درخت `.ui-theme` است، نه Portal. خطر پورتال برای این فاز مصداق نداشت.

## فاز ۳ — اتصال دادهٔ Home

`/projects/`، `/blog/`، `/academy/`. سقف نمایش همان طراحی است (۵ / ۳ / ۳ / ۵ / ۳).
عنوان ثابت بخش‌ها، تگ‌ها، داشبورد داخل کارت محصول، پشته و نتیجهٔ پروژه، دستهٔ مقاله،

## فاز ۴ — دوزبانگی پوستهٔ UI

با تغییر زبان، `dir` صفحه از چیدمان locale عوض می‌شود (فارسی RTL) و درخواست فهرست‌ها
همان `Accept-Language` را می‌فرستد که بک‌اند با آن متن را برمی‌گرداند. متن ثابت پوستهٔ
Home، ناوبری، پاورقی، لودر و ComingSoon از `messages/fa.json` و `messages/en.json`
می‌آید، نه از رشتهٔ داخل کامپوننت. انگلیسی مو‌به‌مو همان متن UI است. فرم‌های تماس و
⌘K متصل به جست‌وجو برای فاز بعد مانده‌اند؛ بک‌اند تغییر نکرده.

## فاز ۵ — یک پوسته برای مسیرهای داخلی

بستهٔ UI صفحه‌ای جز Home و ComingSoon نداشت. مسیرهای گروه `(site)` به `(ui)/(pages)`
منتقل شدند تا همان نوار، لودر، توکن‌های زمردی و فوتر را بگیرند. داده، فرم، سئو و
متن fa/en هر صفحه همان است. عنوان‌ها و ظرف صفحه با زبان بصری UI (خط زمردی، عنوان
بزرگ، سطح `#102A20`) هم‌خوان شدند. خانه و ComingSoon بازطراحی نشدند.

پالت ⌘K چهار مسیر قبلی هدر قدیمی را دارد تا بدون تغییر چیدمان نوار در دسترس بمانند:
`/advisor`، `/estimate`، `/search`، `/profile`. برچسب‌ها همان متن موجود `nav` هستند.

`UI/` به `EmmettWebSite/frontend/` منتقل شد. `EmmettWebSite/legacy-frontend-reference/` حذف شد.
اسکریپت دستی `backend/scripts/generate_brand_assets.py` تصویر مرجع را از
`EmmettWebSite\backend\assets\brand-source\____.jpg` می‌خواند؛ همان فایل است و خروجی برند عوض نشده.

## فاز ۶ — تأیید پوسته: سئو، RTL، دسترس‌پذیری، کاهش حرکت

پوستهٔ پورت‌شده از قبل `lang`/`dir`، لینک پرش، `main`، متادیتای مسیرهای داخلی و قاعدهٔ
سراسری CSS برای `prefers-reduced-motion` را داشت. این فاز فقط شکاف‌های همان پوسته را
بست؛ بک‌اند، توکن‌ها، ThemeToggle، عرض‌ها و اتصال ⌘K به API جست‌وجو دست نخورده‌اند.

- `/products/crm` و `/products/pentestor` دیگر canonical صفحهٔ خانه را به ارث نمی‌برند.
  عنوان و توضیح از `ui.comingSoon` و بقیهٔ متادیتا از `buildPageMetadata` می‌آید.
  **به‌روزرسانی (ADR-0040، بستهٔ ۳):** ‏`/products/pentestor` اکنون در
  `next.config.ts` با ریدایرکت دائمی به `/projects/pentestor` (صفحهٔ واقعیِ
  دیتابیسی) می‌رود و در حالت عادی رندر نمی‌شود؛ `/products/crm` چون هیچ
  متناظر دیتابیسی ندارد همان «به‌زودی» باقی مانده است.
- فلش تماس در RTL برمی‌گردد. نشانگر اسکرول هیرو با `left-1/2` در هر دو جهت وسط می‌ماند.
- نوار برچسب landmark دارد. پالت و کشوی موبایل `dialog` هستند: نام، `aria-modal`،
  قفل فوکوس، Escape و بازگرداندن فوکوس. دکمهٔ جست‌وجوی موبایل فقط هنگام فوکوس دیده می‌شود.
- `MotionConfig reducedMotion="user"` فقط دور پوستهٔ UI است. سه حلقهٔ canvas اگر کاهش
  حرکت خواسته شده باشد یک فریم می‌کشند و تکرار نمی‌شوند.

## فاز ۷ — توکن‌ها روی `:root`، بدون تغییر تم

مقادیر معنایی `:root` همان پالت زمردی بستهٔ UI هستند. پوشش `.ui-theme` از layout و
پوستهٔ وضعیت برداشته شد، چون دیگر لازم نیست. بلوک `.dark` قدیمی (ابسیدین/ایندیگو)
حذف شد تا `prefers-color-scheme` یا کلاس باقی‌مانده نتواند تم را عوض کند. نام
توکن‌ها همان است. لهجه‌ها و سطوح ادیتوریال ADR-0017 سر جایشان ماندند.

`ThemeToggle` و `ThemeProvider` حذف شدند. `next-themes` دیگر وابستگی نیست. سایت یک
تم تیره دارد. بک‌اند، عرض‌ها، نوار و اتصال ⌘K به API جست‌وجو دست نخورده‌اند.

## الحاقیهٔ فاز ۸ — موارد باقی‌مانده

- **بازبینی زندهٔ عرض‌ها (بسته شد):** معیار پذیرش هر ۸ عرض از پیش صریح
  است و در `e2e/responsive.spec.ts` خودکار سنجیده می‌شود: نبود اسکرول
  افقی، حالت ناوبری درست (همبرگر زیر `lg` / دسکتاپ از `lg`)، و نبریدن و
  بیرون‌نزدن متن تیتر (`scrollWidth` در برابر پهنای مرئی + ماندن جعبه
  داخل viewport) — برای خانه و خدمات. مسیر اجرا CI است (در محیط توسعه
  باینری مرورگر در دسترس نیست) و اسکرین‌شات تمام‌صفحهٔ هر عرض در
  آرتیفکت همان اجرا می‌ماند؛ بازبینی چشمی آرتیفکت آخرین اجرای سبز با
  کاربر است.
- **اتصال ⌘K به API (بسته شد):** `command-palette.tsx` مستقل شد؛ فهرست
  ثابت صفحات + نتایج FTS بک‌اند (`globalSearch`، debounce ‏۳۰۰ms، از دو
  نویسه، سقف ۸ نتیجه، گارد پاسخ کهنه، حالت‌های loading/error) و ردیف
  «مشاهدهٔ همهٔ نتایج» به `/search?q=…`. ناوبری کیبورد: جهت‌نما و Enter.
  صفر تغییر بک‌اند؛ ۹ تست واحد + سناریوهای E2E تازه. جزئیات: ADR-0037
  بند ۳-۷.
- **قید Portal (شفاف شد، بدون Portal):** معادل امروزی قید فاز ۲ در
  ADR-0037 بخش ۴ نوشته شد — پالت داخل درخت `.ui-shell` و محدودهٔ توکن
  `:root` می‌ماند؛ کلاس حذف‌شدهٔ `.ui-theme` برنمی‌گردد. قرارداد با تست
  رگرسیون قفل است (رندر درجا، پس‌زمینهٔ توکنی، `inert`، فوکوس، Escape).
- **سندهای تاریخی (دست‌نخورده، با یادداشت وضعیت):** نام
  `legacy-frontend-reference/` در ADR-0016/0017، CHANGELOG و DISCOVERY

  مرجع جاری: ADR-0037 و همین دفترچه) در ADR-0037 بخش ۴ اضافه شد و هیچ
  متن تاریخی بازنویسی نشد.
