# EMMETT GROUP — WEBSITE CREATIVE SPECIFICATION
### Light-Tech / Emerald / AI Engineering Ecosystem

**Status:** Implementation-ready
**Stack:** React + TypeScript + Tailwind CSS + shadcn/ui (Figma Make)

---

## A — Brand Direction

Emmett is an **engineering ecosystem**, not an agency, not a generic AI startup, not a cybersecurity vendor. The site must read as a place where real systems get built — research, engineering, security, product, teaching — all connected through one identity.

Emotional target: *"This feels advanced, but I actually want to explore it."*
Explicitly avoid: *"Another dark AI startup."*

Composition target: **70% technology / 20% human & product / 10% editorial.**
Tonal balance across the site: **55% dark-green environments / 45% light soft-green & ivory environments.** No pure white, no pure black, anywhere.

The existing identity (AI/ML, neural networks, system diagrams, cybersecurity, premium typography, technical metadata, sophisticated motion) is **preserved and evolved** — this is a lightening and warming of the palette and rhythm, not a rebuild.

---

## B — Color System

**Backgrounds (tonal spectrum, not fixed light/dark split):**

| Token | Hex | Use |
|---|---|---|
| Deep Green-Black | `#07130F` | Hero backgrounds, deepest sections |
| Dark Emerald | `#0B1F18` | Primary dark surface |
| Forest Graphite | `#102A20` | Secondary dark surface, cards on dark |
| Emerald Slate | `#16382B` | Elevated dark surface, borders |
| Soft Green | `#DDEDE5` | Light surface, transition zones |
| Warm Green White | `#F1F7F3` | Primary light surface |
| Warm Ivory | `#F4F6F1` | Editorial/content-heavy light surface |

Sections move along a rhythm: Dark Emerald → Forest → Soft Green → Warm White → Ivory → Dark Emerald — never resting flat on one tone for too long.

**Brand (Emerald):**

| Token | Hex | Use |
|---|---|---|
| Primary Emerald | `#1FAE6E` | CTAs, active nav, highlights, node color |
| Secondary Emerald | `#35C98A` | Secondary accents, hover states |
| Deep Emerald | `#0B6B48` | Pressed states, deep accents on light bg |

Rule: premium and intelligent, never neon/RGB-gaming green.

**Supporting network colors:** Soft Mint, Muted Blue, and a very restrained Cyan — used only inside neural-network / system-map visuals, never as UI chrome.

**Text:**
- On dark: `#F3FAF6` (headline), ~70% opacity white for body
- On light: Forest Graphite `#102A20` (headline), ~70% opacity for body

---

## C — Typography

- **Primary typeface:** modern grotesque sans (e.g. Inter, General Sans, or Söhne-equivalent) — large, confident headlines, strong hierarchy, short paragraphs.
- **Monospace:** used specifically for technical metadata — timestamps, tags, coordinates, version numbers, category labels.
- **Editorial serif:** reserved for Library/case-study pull quotes only, where it aids storytelling. Never used site-wide.

Hierarchy: Display (hero headlines, 56–96px fluid) → H1/H2 (section headers) → Body (16–18px, generous line-height) → Metadata (12–13px mono, uppercase, letter-spaced).

---

## D — Grid & Spacing

- 12-column grid on desktop, 4-column on mobile, generous gutters (24–32px desktop, 16px mobile).
- Asymmetry is a deliberate tool, especially on Projects and Library — avoid uniform card grids.
- Section rhythm: consistent vertical padding scale (e.g. 96/128/160px desktop) so the page breathes between tonal shifts.
- Max content width ~1280–1440px, with edge-to-edge treatment for hero visuals and full-bleed imagery.

---

## E — Navigation

**Logo:** EMMETT
**Primary nav:** Services · Products · Projects · Library · Academy · About
**CTA:** Start a Project

**Desktop:** transparent/semi-transparent at top of page. On scroll: dark emerald translucent surface, subtle blur, 1px border, Emerald active-state indicator under the current item.

**Mobile:** clean full-screen drawer, large tap targets, CTA pinned at the bottom of the drawer.

States: default / hover / active / focus (2px Emerald outline) — see Component States (Q).

## K — Projects ("Proof of Work")

Not portfolio thumbnails — **engineering stories.**

Headline: "What we've built."
Subhead: "Real problems. Real constraints. Real systems."

Each project case study covers: Context → Problem → Constraints → Approach → Architecture → Technology → Implementation → Outcome.

Layout: large editorial, asymmetric — big project number, name, industry, short description, large interface image, architecture diagram, technology list, result. Avoid repetitive card grids.

**Interaction:** hover subtly zooms the image, reveals technical metadata, activates an architecture-line animation. Click transitions into a full case study with sticky side nav, large typography, full-width visuals.

## M — Academy ("Learn by Building")

Not Udemy-style — an **engineering learning environment.**

Headline: "Build your way into deeper knowledge."
Subhead: "Courses, paths and practical systems designed around real engineering problems."

**Signature visual — Knowledge Graph:** each topic is a node, dependencies are connections, completed topics illuminate, current topic highlights in Emerald. This should be one of the most memorable visuals on the site.

## P — Content Strategy & Voice

Copy should be: confident, precise, technical, human, short, intelligent — written like engineers who actually build things.

**Avoid entirely:** "We are passionate about…", "We leverage cutting-edge…", "Revolutionizing the future…", "Empowering businesses…", "Next-generation solutions…", "Unlock your potential…"

**Microcopy examples:** Explore system · View architecture · See how it works · Read the case study · Open project · Explore Pentestor · View product · Read the research · Start building · Meet the team.

---

## Q — Component System & States

Reusable components: buttons, navigation, cards, editorial rows, product showcase, technical metadata blocks, architecture diagrams, neural network, knowledge graph, timeline, stats, forms, tags, filters, search.

Every component needs defined states: **Default, Hover, Active, Focus, Disabled, Loading.**
- Focus: 2px Emerald (or indigo on CRM context) outline.
- Loading: skeleton matching the final geometry — never a generic spinner replacing layout.

---

## R — Motion System

Motion is a core differentiator but stays restrained and purposeful:

- **Hero network:** slow node activation, connection flow, subtle parallax, very low overall movement.
- **Scroll reveals:** opacity + 8–16px translate + scale 0.98→1, 400–600ms.
- **Service hover:** system map reorganizes to the selected service.
- **Product scroll:** interface transforms in sync with copy changes.
- **Project hover:** architecture diagram becomes visible.
- **Library hover:** row expands.
- **Academy:** knowledge graph activates on interaction.
- **Navigation:** smooth state transition on scroll (transparent → translucent emerald).

---

## S — Interactive/Signature Systems

1. **System Map** — a recurring neural-network/system visual that changes by page context (general network on Home, engineering network on Services, product ecosystem on Products, security topology on Pentestor, knowledge graph on Academy). This is the site's visual signature.
2. **System Explorer** — hover/click nodes (Software Engineering, AI, Security, Infrastructure, Products, Research) to reveal connected areas, building an interactive mental model of Emmett.
3. **Scroll as Exploration** — scrolling transitions one visual system into the next (Neural Network → Engineering Architecture → Product Interface → Project Architecture → Knowledge Graph) rather than stacking static sections.

Mobile is a **different composition**, not a shrunk desktop (390px baseline):

- **Hero:** text first, network visual underneath.
- **Services:** vertical system index.
- **Products:** horizontal swipe showcase.
- **Projects:** large editorial stories, stacked.
- **Library:** simple rows.
- **Academy:** vertical knowledge graph.

## U — Figma / Build Structure

- Foundations: color tokens, type scale, spacing scale, elevation/blur tokens.
- Components library: nav, buttons, cards, editorial row, product showcase, forms, tags/filters, architecture diagram, neural network, knowledge graph.
- Page templates: Home, Services, Products (+ Pentestor, CRM, Property platform sub-pages), Projects (index + case study), Library (index + article), Academy (index + course), About, Contact.

---

## V — UX & Accessibility

- Maintain WCAG AA contrast even within the emerald/dark palette — verify text-on-dark and text-on-soft-green combinations specifically, since mid-tone greens are contrast-risky.
- All interactive nodes/diagrams need a non-hover, non-mouse path (keyboard focus + visible focus ring; tap equivalents on mobile) — the System Explorer and Knowledge Graph must be fully operable without hover.
- Respect `prefers-reduced-motion`: fall back to simple fades/no parallax for the neural network and scroll-as-exploration transitions.
- Ensure diagrams/network visuals have text-equivalent content (services, products, topics) so the information isn't visual-only.

---

## W — Final Quality Audit Checklist

Before shipping any page, check it against:

- Too dark? Too white? (Neither — tonal spectrum only.)
- Does the green read as premium, not neon/gaming?
- Does the neural network feel intentional and alive, not decorative?
- Does this page have its own distinct personality (see table below)?
- Are animations meaningful, or decorative filler?
- Too many generic cards anywhere?
- Would a talented engineer look at this and think *"these people actually build things"* — or does it read as agency/generic-SaaS/crypto/corporate?
